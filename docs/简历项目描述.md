## 一、简历正文（推荐版本，4 条）

**DocMind — 企业内部知识库智能问答平台**｜AI / Python 全栈开发
技术栈：Python・FastAPI・ChromaDB・BM25・Hybrid RAG・RRF・Rerank・LightRAG・MCP・SSE・Celery・MySQL・Redis・Vue 3

项目概述：面向企业内部制度咨询（HR / 财务 / IT / 法务），用户以自然语言提问，系统经「多路召回 → RRF 融合 → Rerank 精排 → 证据审计」返回**带引用来源的答案**；当证据不足或结论与引用冲突时降级并输出置信度警告，提示人工复核。后端 1.2 万行 Python、测试 2.4 万行，26 篇 ADR，Docker Compose 五服务部署。

- **独立完成 Hybrid RAG 问答全链路**，覆盖四格式文档异步入库（PDF/DOCX/MD/TXT）、向量（ChromaDB，1024 维）+ BM25（rank-bm25 + jieba）双路召回、RRF 融合、qwen3-rerank 语义精排、句级证据定位与 Prompt 组装；并接入 **LightRAG 图谱检索作为第三路召回**，补齐「实体—关系」抽象层以支持跨文档多跳提问，三路统一经 RRF 融合，整套链路可开关一键退回双路且对下游零影响。

- **基于自建评测集完成 Rerank 消融实验**：构造 **100 题评测集**（单文档精确查询 / 跨文档 / 简称口语化 / 蕴含推理 / 超范围五类题型），并混入 **100 篇同领域干扰文档**（共 125 份文档、291 个 chunk）制造真实排序压力；在同一评测集上对比 6 组检索策略，**Rerank 精排将 Hit@1 从 84.7% 提升至 87.1%、MRR 从 0.897 提升至 0.930、nDCG@5 从 0.872 提升至 0.910**，验证了精排对排序质量的实质增益；评测与线上问答复用同一检索链路。

- **设计证据治理与可信降级，抑制 RAG 幻觉**：句级修辞过滤剔除「示例 / 说明」等引用性文本；**三层程序级证据审计**（引用存在性 → 来源一致性 → 句级证据回溯）对答案做生成后校验，冲突时自动改写为拒答并输出 high / medium / low 置信度；引用来源以卡片形式回传文档名、页码与高亮证据句，保证答案依据可追溯。

- **工程化与性能落地**：Token 预算四池子分拆（System / History / Retrieval / Question 独立截断，避免长对话挤占检索结果导致 RAG 静默退化）；问题重写以 13 个歧义信号词触发、正常路径零额外延迟，意图识别采用「规则快速通道 + Flash 模型兜底」；Redis 分布式锁保证入库幂等，Celery 支持批次级 checkpoint 与断点恢复；SSE 流式推送（6 类事件 + 15s 心跳）；用 Locust 完成 4 场景压测（20 并发零失败，检索侧 TTFT P50 800ms），并据压测结果推算落地分级限流阈值。

## 二、精简版（3 条，适合一页简历）

- **Hybrid RAG 全链路**：独立完成四格式文档异步入库与「向量 + BM25 + LightRAG 图谱」三路召回，经 RRF 融合、qwen3-rerank 精排、句级证据定位后组装 Prompt，SSE 流式返回带引用的答案，引用可回溯到文档名 / 页码 / 高亮证据句。

- **评测驱动优化**：自建 100 题评测集并混入 100 篇同领域干扰文档，消融实验证明 **Rerank 将 Hit@1 从 84.7% 提升至 87.1%、MRR 从 0.897 提升至 0.930、nDCG@5 从 0.872 提升至 0.910**；另接 Ragas 生成质量评估（四项均 ≥ 0.80）与 Trace 链路追踪定位各阶段耗时。

- **可信降级与工程加固**：三层证据审计（引用存在性 / 来源一致性 / 句级回溯）在证据不足时降级为拒答并输出置信度警告；Token 四池子预算 + 意图识别快通道 + Redis 分布式锁幂等 + Celery 断点恢复；20 并发压测零失败，检索侧 TTFT P50 800ms。

## 五、面试防守要点

**1. 可以放心讲的**：Rerank 的 Hit@1 / MRR / nDCG@5 提升是本项目**实测**得出，脚本可复现，评测集与语料都在仓库里。

**2. 关于粗排（CoarseRank）——主动讲比被问出来更好。**
同一实验显示：**粗排在本评测集上是负收益**（单独加粗排使 Hit@1 从 0.8471 降到 0.8118），且「粗排+精排」的 MRR/nDCG@5 略低于「仅精排」。根因是粗排按**向量相似度**排序并截断到 top-10，会挤掉 BM25 独有的高价值候选，等于把 RRF 融合成果退化回单路向量。
> 建议答法：「我在强干扰评测集上发现粗排是负收益，定位到它按向量相似度截断会挤掉 BM25 独有候选，所以线上建议关闭粗排、只保留精排。这个结论和项目早期 ADR-024 的乐观判断相反——早期评测集只有 20 份文档、没有干扰，指标触顶所以看不出问题。」
这体现的是**评测能力和批判性思维**，是加分项。

**3. 不要说「Multi-Agent 编排」**：本项目是单条确定性管线（KnowledgePipeline），没有多 Agent 调度器，也没有 Turn Budget（16 LLM / 5 检索 / 8 工具 / 180s）。

**4. 不要说「四层记忆」**：真实实现是 **Token 四池子 + 滑动窗口 + 问题重写**，没有「近窗摘要 / 事件向量 / 实体画像」；摘要压缩在文档中明确标注为**未实现的扩展功能**（`docs/ARCHITECTURE.md` §8.3）。

**5. 压测要敢讲短板**：端到端 P50 7.4s / P99 20s **名义不达标**，根因是 DeepSeek LLM 流式生成占总延迟 89%，检索侧 TTFT 仅 0.8s。主动做归因分析比粉饰数字更显工程判断力。

**6. 阈值口径以代码为准**：`ARCHITECTURE.md` 写粗排阈值 0.3 / top_k 15，但代码 `config.py` 实际是 **0.05 / 10**；多轮测试集文档写 23 轮，代码实际是 **5 Session / 20 轮**。被问到时以「文档与代码有偏差、代码是权威」作答。

**7. 旧版 28 题数据仍可用但要说明出处**：向量 Recall@5 ≈ 0.96、BM25 ≈ 0.95、RRF = 1.000（`docs/tests/TEST_CASES.md` E1–E3）。这是**早期小评测集**结果，因语料仅 20 份且无干扰文档，RRF 后指标触顶（1.000），**无法体现精排增益**——这正是后来重建 100 题评测集的原因。若引用，务必说明是早期结果。
