# 重排消融评测（Ablation Evaluation）

本目录脚本用于构建**可复现的检索质量评测环境**，并对 RRF / Rerank 等检索策略做消融对比。

## 为什么重建评测集

原有 28 题评测集（`eval_test_set.py` / `eval_retrieval.py`）存在两个结构性问题：

1. **语料丢失**：其依赖的 `knowledge_samples/` 被 gitignore，题库期望的 20 份文档在库中一份都不存在（实测 0/20），无法复现。
2. **无区分度**：语料仅 20 份且无干扰文档，RRF 融合后 Recall@5 直接触顶 1.000（28/28）。
   指标天花板掩盖了一切下游优化（粗排、精排）的效果——**无法回答「Rerank 到底有没有用」**。

因此重建为「目标语料 + 同领域干扰文档 + 多题型题库」的评测环境。

## 评测环境构成

| 组成 | 规模 | 说明 |
|:---|:---|:---|
| 目标语料 | 25 份 | LLM 生成的 HR / 财务 / IT / 法务 / 行政制度文档，脚本：`scripts/gen_eval_corpus.py` |
| 干扰语料 | 100 份 | 同属企业制度域但内容无关（薪酬/考勤/安全类），来自既有 KB14 |
| 合计 | **125 份文档 / 291 chunks** | 入库到知识库 kb_id=17 |
| 评测题 | **100 题** | 五类题型，脚本：`scripts/gen_eval_testset.py` + `scripts/finalize_testset.py` |

题型配比：单文档精确查询 30 / 跨文档 25 / 简称口语化 15 / 蕴含推理 15 / 超范围 15。
难度分布：easy 30 / medium 40 / hard 15 / out-of-scope 15。

干扰文档与目标文档**主题高度相似**（例如目标文档 `考勤与请假管理制度.md` 面对干扰文档
`022_病假管理规定.txt`、`020_请假审批流程规定.txt`），这正是排序压力的来源。

## 一键复现

```bash
cd backend

# 1. 生成 25 份目标语料（约 25 次 LLM 调用）
python scripts/gen_eval_corpus.py

# 2. 入库：目标语料 25 份 + 干扰语料 100 份 → 新知识库
#    注意会真实调用 Embedding API（约 291 个 chunk）
python scripts/ingest_eval_corpus.py --name "DocMind评测库A(目标+干扰)" --with-distractors

# 3. 出题并裁剪为标准 100 题
python scripts/gen_eval_testset.py
python scripts/finalize_testset.py

# 4. 跑消融实验（6 组策略 × 100 题，含 200 次 Rerank API 调用，约 8 分钟）
python tests/eval/eval_ablation.py --kb-id 17 --output md
```

评测产出：`backend/ablation_eval.md`（汇总报告）、`backend/ablation_eval.json`（逐题明细）。

## 评测指标

| 指标 | 口径 | 说明 |
|:---|:---|:---|
| Hit@1 / Hit@3 | 文档级 | 最相关文档是否排在第 1 / 前 3 位——**排序质量的直接体现** |
| MRR | 文档级 | 第一个相关结果的倒数排名 |
| nDCG@5 | 文档级 | 考虑排名折损的累计增益 |
| Recall@5 / @10 | 文档级 | 期望文档是否被召回 |
| Precision@5 | 文档级 | top-5 命中的期望文档数 / 期望文档总数 |

> **Precision 为何用文档级**：单份文档约含 8 个 chunk，若用 chunk 级口径，
> P@5 会被分块密度系统性压低（实测恒为 0.200），且与其余文档级指标量纲不一致。

**out-of-scope 题（15 题）不参与主指标计算**：这类题无 ground truth，参与会虚高。

## 关键结果（2026-09-21）

| 策略 | Hit@1 | Hit@3 | MRR | nDCG@5 | Recall@5 |
|:---|---:|---:|---:|---:|---:|
| 仅向量 | 0.8118 | 0.9529 | 0.8817 | 0.8607 | 0.8451 |
| 仅 BM25 | 0.8353 | 0.9176 | 0.8802 | 0.8689 | 0.8549 |
| RRF 融合 | 0.8471 | 0.9294 | 0.8970 | 0.8718 | 0.8510 |
| RRF + 粗排 | 0.8118 | 0.9529 | 0.8817 | 0.8607 | 0.8451 |
| **RRF + 精排(Rerank)** | **0.8706** | **0.9882** | **0.9304** | **0.9102** | **0.9216** |
| RRF + 粗排 + 精排（线上） | 0.8706 | 0.9765 | 0.9265 | 0.9029 | 0.9039 |

### 结论 1：Rerank 有实质增益

相对 RRF 基线，精排 **Hit@1 +2.4pp、MRR +0.033、nDCG@5 +0.038**，Recall@5 从 0.851 升至 0.922。
这证明在**有干扰文档**的真实压力下，语义精排确实能把正确答案提到更前的位置。

### 结论 2：粗排在强干扰场景下是负收益（重要）

单独加粗排使 **Hit@1 从 0.8471 降至 0.8118（−3.5pp）**，MRR / nDCG@5 同步下滑，
且数值与「仅向量」完全一致；「粗排+精排」的 MRR/nDCG@5 也**略低于**「仅精排」。

**根因**：粗排按**向量相似度**排序并截断到 top-10，会挤掉 BM25 独有的高价值候选——
即把 RRF 融合的成果退化回单路向量排序。在候选池本身只有 11-19 条时，
`COARSE_TOP_K=10` 的截断是主要伤害来源。

> 这与 `ADR-024` 的乐观判断相反。差异来源：ADR-024 基于 20 份文档、无干扰的旧评测集，
> 当时指标触顶 1.000，无法暴露问题。**建议线上关闭粗排（`COARSE_RANK_ENABLED=false`）或
> 至少取消其截断**，仅保留精排。

## 已知局限

1. **语料为 LLM 合成**，非真实企业文档；干扰文档主题分布偏 HR/薪酬类。
2. **单文档 chunk 数差异大**（目标文档约 8 个 chunk，干扰文档仅 1 个），
   这使 chunk 级 Precision 失去意义，故采用文档级口径。
3. **粗排结论基于单一阈值**（`COARSE_RANK_THRESHOLD=0.05`、`COARSE_TOP_K=10`），
   未做阈值扫描；不同参数下结论可能变化。
4. **`COARSE_RANK_THRESHOLD` 存在文档与代码不一致**：`ARCHITECTURE.md`/`ADR-024` 写 0.3，
   实际代码为 0.05，本报告以代码为准。
